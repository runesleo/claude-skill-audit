# 不装工具也能做：30 天 AI Skill 审计提示词

把下面这段直接复制给能读取你工作区的 AI 助手。

---

请帮我对本机已安装的 AI Skills 做一次**只读的 30 天审计**。不要修改配置、安装 Hook、删除 Skill、联网传输日志或创建调度器。

1. 先定位当前真实使用的 Claude、Codex 等执行器，以及各自的 `SKILL.md` 目录；只读取为本次审计所必需的信息。
2. 明确列出**每个执行器的日志来源、时间跨度与采集机制是否能证实有效**。无法确认则写「未知/待补采」，**严禁将没有日志解释为零调用**。
3. 统计有证据支持的 30 天调用观测值；每项 Skill 保存名称、覆盖执行器、已记录调用、来源证据和缺口。不要把观察值包装成跨平台总使用量。
4. 检查调用为零的候选项：分别判断可能是「采集缺失」「触发时机缺失」「近期没有适用任务」还是「确实可能冗余」，不根据一次日志就删除。
5. 选出 3 个真实任务作为触发复盘样本，并提出 1–3 个 Skill ON/OFF 对照实验；用质量、耗时、成本、返工对照，尚未测试的指标必须标注「待验证」。
6. 输出一张简洁的表（Skill / 已记录调用 / 执行器覆盖 / 已验证 / 待确认 / 建议），以及三类行动：保留、修复触发、继续观察。对安全或故障应急类 Skill 标明不能凭低调用自动删除。
7. 在最后说明哪些事实经过了回读核验、哪些是推断，并列出下一次审计需要补齐的采集缺口。

只提供建议和可复核证据；需要改变文件或配置时先征得我的明确同意。

---

这不是一个自动替你做判断的「打分魔法」：它的价值是把**未观测、低频和低价值**三件事分开。
